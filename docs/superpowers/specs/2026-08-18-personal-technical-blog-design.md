# Parzival's Lab 个人技术博客设计

## 1. 项目目标

为 GitHub 用户 `ParzivalTheGoat` 创建一个以技术文章为核心的个人博客，并部署到 `https://parzivalthegoat.github.io`。

博客用于承载以下内容方向：

- 网络安全
- Web 安全
- AI
- AI 安全
- 学习笔记
- 个人感悟

首版必须同时支持两种发文方式：在本地编写 Markdown 后推送，以及直接在 GitHub 网页中编辑 Markdown。提交到 `main` 后自动构建和部署。

## 2. 明确不做的内容

- 不创建任何示例文章、占位文章或代写文章。
- 不编写任何 slogan、宣传语或虚构的个人介绍。
- 不提供评论功能。
- 不使用数据库、动态后端或内容管理后台。
- 不在“关于”页面展示真实姓名、邮箱、社交账号或其他联系方式。
- 不绑定自定义域名；首版使用 GitHub Pages 默认域名。

## 3. 技术架构

采用以下技术栈：

- Astro 与 TypeScript
- Astro 内容集合管理 Markdown
- Pagefind Extended 生成中文全文搜索索引
- `@astrojs/rss` 生成 RSS
- `@astrojs/sitemap` 生成站点地图
- GitHub Actions 构建并部署 GitHub Pages

仓库名称为 `ParzivalTheGoat.github.io`。由于仓库符合 GitHub 用户主页的特殊命名规则，站点位于域名根路径，不设置额外 `base`。

发布数据流：

1. 用户创建或修改 Markdown。
2. Astro 内容集合校验元数据。
3. Astro 生成静态页面、RSS 和站点地图。
4. Pagefind 对生成后的 HTML 建立中文搜索索引。
5. GitHub Actions 将构建产物部署到 GitHub Pages。

## 4. 内容模型

文章存放在 `src/content/blog/`。首版该目录为空，不生成文章文件。

每篇文章使用以下字段：

```yaml
title:
description:
publishedAt:
updatedAt:
category:
tags: []
draft: true
```

约束：

- `title`、`description`、`publishedAt`、`category`、`tags` 和 `draft` 必填。
- `updatedAt` 可选，但不得早于 `publishedAt`。
- 每篇文章只能属于一个分类。
- 分类限定为：网络安全、Web 安全、AI、AI 安全、学习笔记、个人感悟。
- 标签可有多个，去除首尾空格后不得为空或重复。
- 标签不得与文章分类同名。
- 生产构建、列表、归档、搜索、RSS 和站点地图均排除草稿。
- 内容错误应在构建阶段失败，并指出对应文章文件和无效字段。

分类负责表达文章所属的大领域；标签负责表达细粒度技术主题。分类页面和标签页面分开生成。

## 5. 信息架构

站点提供以下路由：

- `/`：首页
- `/posts/`：全部文章
- `/posts/[slug]/`：文章详情
- `/categories/`：分类总览
- `/categories/[category]/`：分类文章列表
- `/tags/`：标签总览
- `/tags/[tag]/`：标签文章列表
- `/archive/`：按年份和月份归档
- `/search/`：全文搜索
- `/about/`：关于
- `/rss.xml`：RSS
- `/404.html`：未找到页面

首页只显示站点名称、导航和文章区域，不显示 slogan。没有文章时，文章区域使用中性的空状态，不创建虚构内容。

“关于”页面只显示 `ParzivalTheGoat` 和指向 `https://github.com/ParzivalTheGoat` 的链接。SEO 描述使用中性事实文本“ParzivalTheGoat 的个人技术博客”。

## 6. 页面与交互

### 6.1 全局结构

全局页眉包含站点名称和以下导航：文章、分类、标签、归档、关于、搜索、主题切换。

页脚只保留版权信息、GitHub 链接和 RSS 链接。导航、按钮和链接均采用平面排版，不使用卡片容器。

### 6.2 首页与列表页

- 首页文章按发布日期倒序排列。
- 文章列表使用横向细分隔线和充足留白，不使用卡片。
- 列表展示标题、摘要、发布日期、分类和预计阅读时间。
- 文章列表支持分页。
- 分类和标签以普通文本链接呈现，不使用圆角胶囊。

### 6.3 文章页

- 显示标题、摘要、发布日期、更新时间、分类、标签和预计阅读时间。
- 桌面端提供侧边目录；移动端将目录折叠为普通展开区域。
- 提供代码高亮、代码复制、阅读进度、上一篇和下一篇。
- 代码块使用直角边界与纯色背景，不表现为悬浮卡片。
- 不显示评论区。

### 6.4 搜索

- 使用独立搜索页面，不使用圆角浮层或卡片式结果。
- 搜索结果按普通列表和分隔线排列。
- Pagefind Extended 负责中文和英文索引。
- 没有结果时显示中性状态文本。

## 7. 视觉设计

视觉方向参考 Claude Blog 的克制编辑式风格，但不复制其品牌资产、专有字体或具体页面。

### 7.1 强制约束

- 全站禁止蓝紫渐变背景。
- 全站禁止任何渐变背景。
- 全站禁止圆角边框。
- 默认不使用卡片式设计。
- 如实现过程中确实需要卡片，必须先获得用户明确授权。
- 不用荧光色或赛博朋克视觉表达技术感。
- 层级主要由字体、留白、对齐和细分隔线构成。

### 7.2 浅色主题

- 页面背景：`#F2EEE5`
- 主文字：`#27251F`
- 次级文字：`#6D675E`
- 分隔线：`#C8C1B5`
- 少量强调色：`#A94E32`

浅色主题应具有精美纸质书的阅读质感，避免纯白大面积背景。

### 7.3 深色主题

- 页面背景：`#191815`
- 主文字：`#E9E2D6`
- 次级文字：`#A89F91`
- 分隔线：`#504B42`
- 少量强调色：`#E5A287`

深色主题使用暖墨色，不使用蓝紫色或高饱和荧光色。

### 7.4 字体

- 标题与长文正文使用具有编辑和书籍气质、可合法再分发的开源衬线字体，并提供中文系统衬线字体回退。
- 导航、元数据、标签和代码使用 JetBrains Mono 或合法可打包的同类等宽字体。
- 不直接复制或再分发 Claude 的商业字体。
- 不从第三方字体 CDN 加载资源；字体随站点构建产物一起发布。

### 7.5 动效与响应式

- 只使用必要的淡入、下划线或颜色变化。
- 尊重 `prefers-reduced-motion`。
- 手机、平板和桌面均保持清晰的阅读宽度和足够留白。
- 移动端导航展开后仍使用平面列表与分隔线，不使用圆角抽屉或卡片。

## 8. 主题状态

- 默认跟随操作系统主题。
- 用户手动切换后，在本地保存选择。
- 首次渲染前应用主题，避免页面闪烁。
- 在禁用 JavaScript 时，站点内容仍可阅读，主题回退为系统偏好。

## 9. 错误处理

- 内容模式校验失败时停止构建并输出文件路径及字段原因。
- 空内容集合属于合法状态，站点必须正常构建。
- 搜索索引生成失败时部署失败，不发布缺少搜索资源的版本。
- 未知文章、分类或标签路径返回 404。
- RSS 和站点地图只包含已发布文章。
- GitHub Actions 使用最小必要权限；部署失败保留日志供排查。

## 10. 测试与验收

实现完成前必须验证：

- Astro 类型检查通过。
- 生产构建通过。
- Pagefind 中文搜索索引成功生成。
- 空文章集合可以构建并显示正确空状态。
- 草稿过滤、分类与标签校验有自动化测试。
- 首页、列表、分类、标签、归档、搜索、关于和 404 路由可访问。
- 明暗主题可以切换、保存并在刷新后恢复。
- 键盘导航、焦点样式、颜色对比和减少动画设置可用。
- 在常见手机、平板和桌面宽度下没有横向溢出。
- CSS 和生成页面中没有渐变、非零圆角或未经授权的卡片组件。
- 仓库中没有示例文章、占位文章或 slogan。
- GitHub Pages 工作流配置与 `ParzivalTheGoat.github.io` 根路径一致。

## 11. 后续可变更项

以下内容不属于首版，但架构应允许以后调整：

- 博客名称和中性站点描述
- 自定义域名
- 分类集合
- 字体与色彩细节
- 是否增加系列文章或项目页面

增加评论、卡片式组件或其他视觉结构属于新的设计变更，实施前必须重新获得用户授权。
